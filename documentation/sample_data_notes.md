# CareFlow Sample Data Notes

## 1. Purpose

The purpose of the CareFlow sample dataset is to understand how patients move through different hospital activities. A small sample makes it easier to inspect patient journeys before working with the full dataset.

## 2. Data Source

The project uses synthetic hospital event data generated with Python. No real patient information is used.

The existing dataset contains event records for 500 synthetic patients. A separate sample of 20 patients is planned for initial inspection and testing.

## 3. Event Log Structure

Each row represents one event in a patient's hospital journey.

| Column | Description |
|---|---|
| case_id | Identifies the patient journey |
| event_id | Uniquely identifies an event |
| event_order | Shows the sequence of events |
| activity | Hospital activity performed |
| timestamp | Date and time of the event |
| department | Department responsible for the activity |
| journey_type | Indicates the generated journey pattern |
| is_loop_back | Flags a repeated consultation when applicable |
| data_source | Identifies the data as synthetic |

## 4. Example Patient Activities

A patient journey may include:

Registration → Triage → Doctor Consultation → Lab Test → Treatment → Discharge

Some journeys may include repeated activities, such as another doctor consultation. These repeated steps help the team investigate possible process inefficiencies.

## 5. Initial Review Checklist

- Confirm that the sample contains the expected number of unique patients.
- Check that the required columns are present.
- Inspect missing values and duplicate event IDs.
- Check timestamp formats and event order.
- Review normal journeys and journeys containing repeated activities.

## 6. Project Workflow

Python generates the synthetic event log → CSV stores the event records → BigQuery stores the raw data → dbt transforms the data into a standardized format.

Each step must be tested before it is reported as complete.
